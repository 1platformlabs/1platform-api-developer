# Gestión de contenido

Esta guía cubre el lado de **escritura** del catálogo: crear un ítem, adjuntarle sus archivos y su portada, y publicarlo. El
lado de lectura está en [Exploración del catálogo](/docs/saas/atlas-api/catalog-browsing).

Estas operaciones aceptan **sólo** el JWT de una sesión de operador o administrador del tenant
([Inicio de sesión de operador](/docs/saas/atlas-api/authentication#inicio-de-sesion-de-operador)). El tenant lo fija ese
JWT, no el header `X-Tenant-Slug`; puede enviarlo igual, pero no cambia el tenant sobre el que escribe. Una clave de
integración no sirve aquí: responde `401 UNAUTHORIZED`. Todas las operaciones de esta página:
[Referencia de API → content](/api-reference/atlas-api#tag/content).

Crear, listar y leer un ítem por su `id` exige el rol de operador (`403 INSUFFICIENT_ROLE` si falta); editar, publicar,
archivar y subir o quitar archivos y portadas exigen además un permiso de contenido concreto
(`403 INSUFFICIENT_PERMISSION`, con el permiso que falta). Las ediciones, publicaciones, archivados y cambios de archivos y
portadas quedan registrados en la auditoría del tenant; la creación del ítem, no.

## El ciclo de vida de un ítem

Un ítem está en uno de cuatro estados: `draft` (no visible), `scheduled` (anunciado como próximo), `published` (visible y
entregable a quien tenga derecho de acceso) y `archived` (retirado, pero conservado). No hay borrado físico: borrar un ítem lo
archiva, para que los enlaces, la auditoría y los derechos de acceso sigan siendo coherentes.

## Paso 1 — Cree el ítem como borrador {#paso-1--crea-el-ítem-como-borrador}

`POST /content/items` crea el ítem. Créelo en `draft` (el valor por defecto) para que no aparezca en el catálogo antes de
tener archivo y portada. El slug es único por tenant; si ya existe, responde `409 CONTENT_SLUG_TAKEN`. Los tipos de contenido
válidos (`kind`) están en la Referencia de API e incluyen `audio`.

```bash
curl -s -X POST "$ATLAS_BASE/content/items" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT" -H "Content-Type: application/json" \
  -d '{ "slug": "la-maquina-del-tiempo", "kind": "book", "title": "La máquina del tiempo",
        "metadata": { "language": "es", "genres": ["ciencia-ficcion"] } }'
```

Guarde el `id` que devuelve: todas las operaciones siguientes lo usan. Los metadatos son libres, pero en esta operación y en
la edición algunas claves se validan: `language` se normaliza a un código de idioma (el valor original queda en
`language_raw`), `tags` admite hasta 40 valores, `people` hasta 80 créditos con nombre y `faq` hasta 12 preguntas
frecuentes `{ q, a }`; un valor inválido en cualquiera de ellas responde `422`. El resto de las claves se
guarda tal como llega. El filtro de género del catálogo busca tanto en `genres` como en `tags`. Las banderas `metadata.access` son sólo una pista
para la interfaz: el acceso real lo deciden los [derechos de acceso](/docs/saas/atlas-api/entitlements).

## Paso 2 — Adjunte el archivo {#paso-2--adjunta-el-archivo}

Para tenants que entregan archivos, suba el binario con `POST /content/items/{item_id}/assets` (formulario multipart con el
formato, `pdf`, `epub`, `mobi`, `mp3` o `m4a`, y el archivo). Subir otra vez el mismo formato reemplaza el anterior;
`DELETE /content/items/{item_id}/assets/{fmt}` lo quita y es seguro de reintentar. Para audiolibros,
`PUT /content/items/{item_id}/audio` define narrador, idioma y capítulos, y el campo `chapter` de la subida asocia el audio
a un capítulo ya declarado.

```bash
curl -s -X POST "$ATLAS_BASE/content/items/$ITEM_ID/assets" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT" -F "format=epub" -F "file=@la-maquina-del-tiempo.epub"
```

Atlas valida la subida antes de guardar nada: un formato no admitido responde `400 ASSET_FORMAT_INVALID`, un formato que la
forma de entrega del tenant o el tipo del ítem no puede servir `400 ASSET_STRATEGY_MISMATCH`, un tipo de archivo que no
corresponde al formato `400 ASSET_CONTENT_TYPE_MISMATCH`, un archivo vacío `400 ASSET_FILE_REQUIRED`, un archivo demasiado
grande `413 ASSET_TOO_LARGE` (con el máximo en `max_bytes`) y un tenant sin almacenamiento configurado
`409 ASSET_STORE_UNCONFIGURED` (avise a 1Platform Labs). Si el almacenamiento
falla, recibe `502 ASSET_STORAGE_FAILED` o `503 MEDIA_UNAVAILABLE`: reintente más tarde.

## Paso 3 — Suba la portada {#paso-3--sube-la-portada}

`POST /content/items/{item_id}/cover-image` recibe una imagen JPEG, PNG o WebP y deja la URL pública en el ítem, así el
catálogo la muestra sin firmar URLs en cada vista. Para quitarla use `DELETE /content/items/{item_id}/cover-image`, que borra
también el archivo; no envíe `null` en una edición.

```bash
curl -s -X POST "$ATLAS_BASE/content/items/$ITEM_ID/cover-image" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT" -F "file=@portada.jpg"
```

## Paso 4 — Publique {#paso-4--publica}

`POST /content/items/{item_id}/publish` pasa el ítem a `published` desde borrador, programado o archivado. Si ya estaba
publicado responde `409 CONTENT_ALREADY_PUBLISHED`, así que puede tratar ese código como éxito al reintentar.

```bash
curl -s -X POST "$ATLAS_BASE/content/items/$ITEM_ID/publish" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT"
```

Desde ese momento los miembros con derecho de acceso pueden pedir su
[ticket de entrega](/docs/saas/atlas-api/content-delivery). Publicar no exige que el ítem tenga archivo: si todavía no
tiene ninguno descargable, el listado normal de `GET /public/catalog` no lo muestra y aparece sólo entre los próximos
(`coming_soon=true`). Por eso conviene adjuntar el archivo antes de publicar.

## Paso 5 — Edite o retire {#paso-5--edita-o-retira}

- **Editar:** `PATCH /content/items/{item_id}` cambia sólo los campos que envía. `metadata` se **reemplaza** completo, no se
  fusiona: envíe el objeto entero. La única excepción es `metadata.assets`, que administra Atlas: si no lo envía se
  conserva, y las claves de almacenamiento que envíe se ignoran. Cambiar el slug a uno ocupado responde
  `409 CONTENT_SLUG_TAKEN`.
- **Retirar:** `POST /content/items/{item_id}/archive` o `DELETE /content/items/{item_id}` lo archivan. Ambas son
  idempotentes y seguras de reintentar.
- **Leer:** `GET /content/items` lista todos los estados (a diferencia del catálogo público, que sólo muestra lo publicado);
  `GET /content/items/{item_id}` lee uno. `GET /content/items/by-slug/{slug}` es la excepción de esta página: resuelve el
  tenant por `X-Tenant-Slug`, sin sesión devuelve sólo ítems publicados o programados, y con el JWT de un operador de ese
  tenant devuelve el ítem en cualquier estado.
