# Derechos de acceso

Un **derecho de acceso (*entitlement*)** es el registro que dice «este miembro puede consumir este contenido». Atlas guarda
sus propios derechos de acceso por tenant y la [entrega de contenido](/docs/saas/atlas-api/content-delivery) los consulta en
cada ticket. Se escriben de cuatro maneras:

- un **operador** los concede o revoca a mano;
- el **acceso gratuito automático** del tenant, si está activado, los concede al iniciar sesión o al pedir un ticket;
- el **proveedor de pagos del tenant** los concede o revoca con un [webhook](/docs/saas/atlas-api/webhooks) tras cada compra,
  cancelación o vencimiento;
- el propio **miembro**, al activar la prueba gratuita del tenant o al reconciliar una compra recién hecha.

Todas las operaciones van con `X-Tenant-Slug` y un JWT
([Referencia de API → entitlement](/api-reference/atlas-api#tag/entitlement)).

## Alcance de un derecho de acceso

Cada derecho de acceso tiene un **alcance** (`scope`: `item`, `series`, `plan` o `live`) y una **referencia** (`scope_ref`)
que identifica qué cubre: un ítem, una serie, un plan o una emisión en vivo.

- **El comodín `*` sólo tiene efecto con `scope: "item"`** y cubre todo el catálogo; es lo que escribe el acceso gratuito
  automático. Con `scope: "plan"`, `*` se rechaza con `422`: un plan siempre se referencia por su identificador.
- **Al entregar un ítem**, Atlas busca un derecho de alcance `item` para ese ítem (o el comodín). En los tenants con planes
  configurados, un plan pagado activo desbloquea además todo el catálogo. Un derecho de alcance `series` no habilita por sí
  solo la entrega de un ítem.
- Un derecho de acceso sin fecha de vencimiento es permanente; con `expires_at` sirve para alquileres o pruebas.

## Paso 1 — Vende el acceso

Un miembro con sesión pide un enlace de pago con `POST /entitlements/checkout`; un comprador sin sesión, con
`POST /entitlements/guest-checkout`, que sólo pide su correo (crea o reutiliza al miembro y responde igual en los dos casos,
para no revelar qué correos existen). En ambos casos redirige al comprador a la `url` que devuelve.

```bash
curl -s -X POST "$ATLAS_BASE/entitlements/checkout" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT" -H "Content-Type: application/json" \
  -d '{ "plan_ref": "anual", "return_url": "/cuenta?refreshed=1", "scope": "plan", "scope_ref": "anual" }'
```

Usa como `return_url` una ruta del sitio o una URL `https`; `guest-checkout` rechaza cualquier otra con
`422 INVALID_RETURN_URL`. Estas operaciones **no**
conceden el acceso: lo concede el webhook del proveedor cuando el pago se confirma.

## Paso 2 — Reconcilia al volver del pago

El comprador suele volver antes de que llegue el webhook. Al volver, llama **una vez** a `POST /entitlements/refresh` con el
mismo alcance: Atlas consulta al proveedor y, si el pago está confirmado, guarda el derecho de acceso de inmediato.
`refreshed` es `true` sólo si esta llamada lo escribió. Es idempotente; no lo llames en un bucle.

```bash
curl -s -X POST "$ATLAS_BASE/entitlements/refresh" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_JWT" -H "Content-Type: application/json" \
  -d '{ "scope": "plan", "scope_ref": "anual" }'
```

Si el proveedor no responde, recibes `503 PROVIDER_UNAVAILABLE`: muestra un estado de «procesando tu compra» y deja que el
webhook complete el acceso.

## Paso 3 — Consulta el acceso de un miembro

`GET /entitlements/check` responde si un miembro tiene un derecho de alcance `item` sobre un ítem (incluido el comodín);
no tiene en cuenta planes ni series. `GET /entitlements/by-member/{member_id}` lista todos sus derechos de acceso.

Las dos exigen el JWT. Un miembro sólo puede consultarse a sí mismo: con otro `member_id` recibe `403 MEMBER_MISMATCH`.
Un operador puede consultar a cualquier miembro de su tenant. Para decidir si mostrar el muro de pago, no hace falta
consultar antes: pide el ticket de entrega y reacciona a `ENTITLEMENT_DENIED` o `FREEMIUM_GATE_BLOCKED`.

## Paso 4 — Concede o revoca a mano (operador)

Con un JWT de operador, `POST /entitlements` concede un derecho de acceso a un miembro existente (`404 MEMBER_NOT_FOUND` si no
existe) y `DELETE /entitlements/{entitlement_id}` lo revoca (`404 ENTITLEMENT_NOT_FOUND` si no es de este tenant).
`granted_by` es un texto libre para tu auditoría; si no lo envías, queda `webhook`, así que envía un valor propio
(por ejemplo, `operator`) para distinguir las concesiones manuales.

```bash
curl -s -X POST "$ATLAS_BASE/entitlements" -H "X-Tenant-Slug: $TENANT_SLUG" \
  -H "Authorization: Bearer $ATLAS_OPERATOR_JWT" -H "Content-Type: application/json" \
  -d '{ "member_id": "<MEMBER_ID>", "scope": "item", "scope_ref": "<CONTENT_ID>", "granted_by": "operator" }'
```

## Prueba gratuita

Si el tenant tiene una prueba configurada, el miembro la activa con `POST /entitlements/trial`, que le concede el plan de
prueba por los días configurados. Si no hay prueba, o el tenant la limita a una por miembro y ya la usó, la respuesta lo
indica con `granted: false` y un motivo, sin error.
