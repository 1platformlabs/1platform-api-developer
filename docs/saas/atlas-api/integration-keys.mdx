# Claves de integración

Una **clave de integración** (`ak-int-…`) permite que un servidor tuyo actúe sobre un tenant sin la sesión de ninguna
persona: por ejemplo, el sistema de ventas que, tras una compra, crea al comprador como miembro y le muestra un enlace de
acceso. Es una credencial distinta del [JWT de miembro u operador](/docs/saas/atlas-api/authentication).

## Cómo se obtiene

Las claves las emite el equipo de 1Platform Labs; ni el panel del tenant ni la API pública permiten crearlas. Al emitirla se
fijan tres cosas que tú no puedes ampliar después:

- **el tenant** al que pertenece (o toda la plataforma, para las integraciones internas de 1Platform Labs);
- **las capacidades**: qué operaciones puede llamar;
- **la fecha de vencimiento**: como máximo 365 días para una clave de tenant y 90 para una de plataforma.

Hay como máximo **una clave activa por tenant e integración**: rotar una clave reemplaza a la anterior, no convive con ella.
Guárdala como un secreto (fuera del código del cliente, de los registros y del control de versiones). Atlas no puede
recuperarla: si se pierde o se filtra, pide una nueva.

## Cómo se usa

Envía la clave como `Authorization: Bearer ak-int-…`. El tenant sale de la clave, así que **no** envíes `X-Tenant-Slug`.

```bash
curl -s -X POST "$ATLAS_BASE/integrations/bower/v1/members/upsert" \
  -H "Authorization: Bearer $ATLAS_INTEGRATION_KEY" \
  -H "Content-Type: application/json" -d '{ "email": "comprador@example.com" }'
```

Las operaciones disponibles para un tenant son las de aprovisionamiento de miembros
([Referencia de API → integrations:bower](/api-reference/atlas-api#tag/integrations-bower)):

| Operación | Para qué |
|---|---|
| `POST /integrations/bower/v1/members/upsert` | Crear o actualizar un miembro por correo y obtener un enlace de acceso. |
| `POST /integrations/bower/v1/members/{member_id}/issue-magic-link` | Obtener un enlace de acceso nuevo para un miembro existente. |

Las operaciones de gestión de contenido (`/content/*`), de derechos de acceso (`/entitlements/*`) y de administración
(`/admin/*`) **no** aceptan una clave de integración: responden `401 UNAUTHORIZED` y exigen el JWT de un operador o miembro.
Las operaciones `/platform/*` que verás en la Referencia de API sí usan claves, pero son la superficie interna con la que
1Platform Labs aprovisiona y opera tenants; si tu caso necesita escribir catálogo con una clave, coordínalo con ese equipo.

## El orden de un aprovisionamiento

1. Tras la compra, llama a `members/upsert`. Es idempotente por tenant y correo: repetirlo no duplica al miembro.
2. Muestra el enlace de acceso que devuelve **en ese momento**. Es de un solo uso y vence en minutos.
3. Si el comprador vuelve más tarde a la página de acceso, pide un enlace nuevo con `issue-magic-link`. Nunca guardes el
   enlace: un registro filtrado no debe servir para entrar.

## Detecta el vencimiento antes del corte

Una clave vencida deja de funcionar de golpe, y el día de vencimiento lo conoce quien la emitió, no tu integración. Atlas te
avisa de dos maneras:

- **Durante los últimos 14 días** de vida de la clave, cada respuesta exitosa trae el header `X-Atlas-Key-Expires-At` con
  la fecha y hora de vencimiento (UTC). Vigílalo y alerta en cuanto aparezca: es la señal para pedir la renovación.
- **Una vez vencida**, la clave responde `401 INTEGRATION_KEY_EXPIRED`, distinto de `INTEGRATION_KEY_INVALID`. No los trates
  igual: uno pide renovar la clave; el otro, revisar cuál estás enviando.

## Errores de la clave

- `401 INTEGRATION_KEY_REQUIRED`: no enviaste una clave `ak-int-…`.
- `401 INTEGRATION_KEY_INVALID`: la clave no existe, fue revocada o el secreto no coincide.
- `401 INTEGRATION_KEY_EXPIRED`: la clave venció.
- `403 INTEGRATION_CAPABILITY_MISSING`: la clave es válida pero no tiene la capacidad que pide la operación; la respuesta
  nombra la capacidad requerida.
- `404 TENANT_NOT_FOUND` o `404 MEMBER_NOT_FOUND`: el tenant o el miembro ya no existe. Un miembro de otro tenant también
  responde `404`, para que una clave filtrada no pueda averiguar qué identificadores existen.

Estos errores llegan anidados en `detail`; consulta [Errores](/docs/saas/atlas-api/errors).
