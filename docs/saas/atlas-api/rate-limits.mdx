# Límites de uso

La Atlas API limita el ritmo **por operación**, no de forma uniforme: los límites se concentran en las superficies públicas
y anónimas, y en las que pueden abusarse (sugerencias de búsqueda, enlaces de pago sin sesión, descargas). Construya su
cliente para **reaccionar** a las respuestas de abajo en lugar de fijar umbrales: los valores pueden cambiar.

## Qué cuenta para el límite

La cuenta se lleva con claves distintas según la superficie: por cliente (dirección y navegador) en las lecturas anónimas,
por clave en las operaciones con clave de integración y por sesión en las escrituras de un miembro.

Hay una excepción importante: `GET /tenants/by-host` cuenta por dirección de origen, y todo el tráfico que pasa por el
proxy de entrada comparte esa dirección. Su límite es, en la práctica, **compartido entre todos los clientes**. Llámelo una
vez al configurar su integración (o en su prueba de humo) y guarde el resultado; no lo llame en cada solicitud.

## Qué respuestas esperar

- **`429 RATE_LIMITED`**: superó el límite de la operación. Espere y reintente con espera creciente.
- **`429 DOWNLOAD_RATE_LIMITED`**: demasiadas solicitudes de entrega seguidas; trae `Retry-After`.
- **`503 CATALOG_BUSY`**: el catálogo está saturado y descarta solicitudes para proteger al resto de la API; trae
  `Retry-After`.

Cuando la respuesta trae `Retry-After`, respételo antes que su propio cálculo.

:::note En QA el 429 no trae el cuerpo estándar
El `429 RATE_LIMITED` con el cuerpo estándar sólo está activo en producción. En QA el límite también corta, pero el `429`
llega con un `detail` de texto y sin código. No use QA para probar su manejo de límites: simúlelo en sus pruebas.
:::

## Cómo reintentar

Reintente automáticamente sólo las lecturas y las operaciones idempotentes. Use espera exponencial con variación aleatoria:

```javascript
async function conReintento(url, init, { maxIntentos = 4 } = {}) {
  for (let intento = 0; ; intento++) {
    const res = await fetch(url, init);
    if (![429, 503].includes(res.status) || intento >= maxIntentos) return res;
    const retryAfter = Number(res.headers.get("Retry-After"));
    const base = retryAfter > 0 ? retryAfter * 1000 : 500 * 2 ** intento;
    await new Promise((r) => setTimeout(r, base * (0.8 + Math.random() * 0.4)));
  }
}
```

## Cómo no llegar al límite

- **Guarde en caché las lecturas públicas** (catálogo, detalle, portada del sitio): cambian poco.
- **Espere una pausa en la escritura** antes de llamar a `GET /public/search/suggest`.
- **Tras un pago, llame a `POST /entitlements/refresh` una sola vez**, no consulte el acceso en un bucle.
- **Reutilice la sesión** del miembro durante toda su vida y refrésquela; no pida un enlace de acceso por solicitud.
