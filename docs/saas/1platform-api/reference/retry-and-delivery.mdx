# Reintentos y entrega

## Garantía de entrega

**Entrega con reintentos limitados; puede haber duplicados y eventos no entregados. Requiere conciliación.** Un receptor puede procesar un evento cuya respuesta se pierda. No hay garantía de exactamente una vez ni de que todo evento llegue.

Deduplique antes de aplicar efectos y consulte periódicamente las transacciones. El recorrido está en [Cobrar y conciliar](/docs/saas/1platform-api/pagos-en-linea/cobrar-y-conciliar).

El historial durable y su despacho necesitan habilitación; no dé por hecho el modo por la existencia de la ruta. Consulte su cobertura y disponibilidad en [Entrega y recuperación](/docs/saas/1platform-api/plataforma/webhooks-entregas). Los valores operativos no son un SLA: dependen de configuración, capacidad, pausas y disponibilidad del receptor.

## Respuestas del receptor

| Respuesta | Tratamiento |
|---|---|
| `2xx` | Entrega confirmada al receptor; termine el efecto comercial mediante su propia cola |
| `3xx` | No se sigue la redirección; el intento falla |
| `4xx`, `429`, `5xx` | Se registra el fallo y se aplican los reintentos limitados |
| Error de conexión, DNS o timeout | Fallo de transporte; no demuestra que el receptor no procesó la petición |
| Destino revocado o no autorizado | La entrega durable queda bloqueada; no se redirige a una URL nueva |

Responda `200` o `202` después de guardar de forma durable la recepción y antes del trabajo pesado. El timeout inicial por intento es de 10 segundos. Una respuesta rápida sin registrar el evento no protege a su aplicación de una caída posterior.

## Carga, pausas y agotamiento

El envío existente puede perder un evento si no consigue turno de envío; no dispone de una cola histórica. En el modo durable, la pausa conserva los pendientes y cada próximo intento se programa en la cola. Al agotar el ciclo se conserva el resultado `failed`, y sólo una recuperación autorizada puede reencolarlo. Un `delivered` no se reenvía desde la API de recuperación.

## Headers

Verifique `X-Webhook-Signature` y `X-Webhook-Timestamp` según [Seguridad de webhooks](/docs/saas/1platform-api/reference/webhooks-security). En modo durable, use además `X-1Platform-Event-Id` para deduplicar; no use la firma cambiante como clave de negocio. `Content-Type` es `application/json`. El token externo sólo se adjunta cuando el destino tiene la verificación exigida; registrar un dominio no equivale a verificarlo por DNS.
