# Exploración del catálogo

El catálogo público es **anónimo** y está acotado al tenant: puede renderizarlo en páginas indexables o en el servidor sin
sesión. La sesión y los [derechos de acceso](/docs/saas/atlas-api/entitlements) sólo controlan la
[entrega](/docs/saas/atlas-api/content-delivery) del contenido.

Envíe `X-Tenant-Slug` en cada llamada. Con un slug mal escrito no recibe error sino el catálogo del tenant por defecto,
normalmente vacío; si ve `total: 0` donde esperaba contenido, revise primero el slug
([Resolución de tenant](/docs/saas/atlas-api/tenant-resolution)).

## Paso 1 — Liste el catálogo {#paso-1--lista-el-catálogo}

`GET /public/catalog` devuelve una página de ítems publicados y el `total` de coincidencias. `total` cuenta siempre con los
mismos filtros que la página, así que úselo para paginar.

```bash
curl -s "$ATLAS_BASE/public/catalog?page=1&page_size=20&sort=recent" -H "X-Tenant-Slug: $TENANT_SLUG"
```

Puede ordenar y filtrar por tipo de contenido, género, disponibilidad en web o app, contenido con audio y lanzamientos
próximos. El género coincide con las etiquetas **o** con los géneros que el operador cargó en los metadatos del ítem, con
semántica «cualquiera de»: repita el parámetro para combinar varios. Los valores aceptados de cada parámetro están en
[Referencia de API → public](/api-reference/atlas-api#tag/public); no los fije en su cliente sin consultarla.

Si el catálogo está saturado, puede responder `503 CATALOG_BUSY` con un header `Retry-After`: espere ese intervalo y
reintente. Es una respuesta deliberada para proteger al resto de la API, no una caída.

## Paso 2 — Abra el detalle por slug {#paso-2--abre-el-detalle-por-slug}

Las páginas de detalle se identifican por el slug legible del ítem, el mismo que aparece en el listado:

```bash
curl -s "$ATLAS_BASE/public/items/la-maquina-del-tiempo" -H "X-Tenant-Slug: $TENANT_SLUG"
```

Un slug que no existe en este tenant, o que no es visible públicamente, responde `404 CONTENT_NOT_FOUND`. Para la entrega
necesitará el `id` del ítem, no su slug.

## Paso 3 — Busque {#paso-3--busca}

`GET /public/search` busca texto en el catálogo publicado y agrupa los resultados por tipo de contenido.

```bash
curl -s "$ATLAS_BASE/public/search?q=maquina%20del%20tiempo" -H "X-Tenant-Slug: $TENANT_SLUG"
```

Valide la consulta en su cliente antes de enviarla: una consulta vacía o demasiado larga responde `422` con la lista de
errores de validación. Una búsqueda que no puede completarse en el servidor no da error: devuelve cero resultados, así que
muestre un estado de «sin resultados» y no un error.

## Paso 4 — Agregue autocompletado {#paso-4--agrega-autocompletado}

Para una caja de búsqueda con sugerencias, use `GET /public/search/suggest`, más liviano y con su propio límite de uso
([Referencia de API → public-search](/api-reference/atlas-api#tag/public-search)). Espere una pausa en la escritura antes de
llamarlo.

```bash
curl -s "$ATLAS_BASE/public/search/suggest?q=maq" -H "X-Tenant-Slug: $TENANT_SLUG"
```

Aquí los errores de entrada llegan como `400` con código (`SEARCH_QUERY_EMPTY`, `SEARCH_QUERY_TOO_LONG`) en lugar de `422`.
Trate los dos formatos igual: son errores de su entrada y no se reintentan.

## Otras lecturas públicas

Para armar la portada y las páginas de un sitio hay más operaciones públicas: destacados (`GET /public/featured`), ítems
relacionados (`GET /public/items/{slug}/related`), géneros (`GET /public/genres`), planes (`GET /public/plans`) y la
portada completa (`GET /public/home`), entre otras. Todas: [Referencia de API → public](/api-reference/atlas-api#tag/public).

Estas respuestas cambian poco. Guárdelas en caché de su lado en lugar de pedirlas en cada vista de página
([Límites de uso](/docs/saas/atlas-api/rate-limits)).
