# Límites de uso

La Atlas API limita el ritmo **por operación**, no de forma uniforme: los límites se concentran en las superficies públicas
y anónimas, y en las que pueden abusarse (sugerencias de búsqueda, enlaces de pago sin sesión, descargas). Construye tu
cliente para **reaccionar** a las respuestas de abajo en lugar de fijar umbrales: los valores pueden cambiar.

## Qué cuenta para el límite

La cuenta se lleva con claves distintas según la superficie: por cliente (dirección y navegador) en las lecturas anónimas,
por clave en las operaciones con clave de integración y por sesión en las escrituras de un miembro.

Hay una excepción importante: `GET /tenants/by-host` cuenta por dirección de origen, y todo el tráfico que pasa por el
proxy de entrada comparte esa dirección. Su límite es, en la práctica, **compartido entre todos los clientes**. Llámalo una
vez al configurar tu integración (o en tu prueba de humo) y guarda el resultado; no lo llames en cada solicitud.

## Qué respuestas esperar

- **`429 RATE_LIMITED`**: superaste el límite de la operación. Espera y reintenta con espera creciente.
- **`429 DOWNLOAD_RATE_LIMITED`**: demasiadas solicitudes de entrega seguidas; trae `Retry-After`.
- **`503 CATALOG_BUSY`**: el catálogo está saturado y descarta solicitudes para proteger al resto de la API; trae
  `Retry-After`.

Cuando la respuesta trae `Retry-After`, respétalo antes que tu propio cálculo.

:::note QA no aplica el 429 estándar
El `429 RATE_LIMITED` con el cuerpo estándar sólo está activo en producción. No uses QA para probar tu manejo de límites:
simúlalo en tus pruebas.
:::

## Cómo reintentar

Reintenta automáticamente sólo las lecturas y las operaciones idempotentes. Usa espera exponencial con variación aleatoria:

```javascript
async function conReintento(url, init, { maxIntentos = 4 } = {}) {
  for (let intento = 0; ; intento++) {
    const res = await fetch(url, init);
    if (![429, 503].includes(res.status) || intento >= maxIntentos) return res;
    const retryAfter = Number(res.headers.get("Retry-After"));
    const base = retryAfter > 0 ? retryAfter * 1000 : 500 * 2 ** intento;
    await new Promise((r) => setTimeout(r, base * (0.8 + Math.random() * 0.4)));
  }
}
```

## Cómo no llegar al límite

- **Guarda en caché las lecturas públicas** (catálogo, detalle, portada del sitio): cambian poco.
- **Espera una pausa en la escritura** antes de llamar a `GET /public/search/suggest`.
- **Tras un pago, llama a `POST /entitlements/refresh` una sola vez**, no consultes el acceso en un bucle.
- **Reutiliza la sesión** del miembro durante toda su vida y refréscala; no pidas un enlace de acceso por solicitud.
