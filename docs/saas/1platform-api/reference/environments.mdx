# Entornos

La 1Platform API tiene dos entornos con datos y cuentas separados. Las credenciales de uno no sirven en el otro:
una clave de QA devuelve `401` contra producción, y al revés.

| Entorno | URL base | OpenAPI |
|---|---|---|
| Producción | `https://api.1platform.pro/api/v1` | [openapi.json](https://api.1platform.pro/openapi.json) |
| QA | `https://api-qa.1platform.pro/api/v1` | [openapi.json](https://api-qa.1platform.pro/openapi.json) |

## Qué esperar de cada uno

- **Producción** es el entorno en vivo: datos reales y cobros reales. La [Referencia de API](/api-reference/1platform-api)
  describe el contrato de producción.
- **QA** es el entorno de integración de la plataforma, **no un entorno de pruebas estable**: recibe los cambios
  antes que producción, puede tener operaciones que producción todavía no tiene y puede cambiar o quedar
  indisponible sin aviso. Úsalo para probar tu integración sin datos reales, y valida contra producción lo que vayas
  a publicar. Si necesitas el contrato exacto que corre en QA en un momento dado, lee su `openapi.json`.

Para obtener acceso a QA, pídelo a tu contacto comercial. Las claves de los dos entornos llevan los mismos prefijos
(`ak-` y `sk-`); lo único que las distingue es el entorno donde se emitieron.

:::warning[No mezcles entornos en un mismo despliegue]
Trata la URL base y las claves como un único conjunto. Lo más simple son dos archivos de entorno (`.env.qa` y
`.env.prod`) y una sola variable `API_BASE_URL` que tu cliente lea al iniciar.
:::

## Lo que no se comparte entre entornos

| Aspecto | Detalle |
|---|---|
| Cuentas y datos | Cada entorno tiene los suyos; nada se copia de uno a otro |
| Claves | Una clave sólo se canjea en el entorno donde se emitió |
| Configuración de webhooks | Dominios, eventos y secreto de firma se configuran por separado en cada entorno; hay un `webhook_secret` por espacio de trabajo |

## Errores comunes

- **`401` en producción con claves de QA** (o al revés): la causa más común de «mi clave es válida pero no puedo
  autenticarme». Revisa a qué host apunta tu cliente.
- **Validar el formato de la clave**: algunas claves antiguas no llevan prefijo y siguen funcionando. Trata las
  claves como cadenas opacas y no valides su longitud ni su alfabeto.

## Distinguir el entorno en tiempo de ejecución

`GET /health/` responde sin credenciales e incluye `data.environment` (`production` o `qa`). Usa la ruta con la
barra final: sin ella, la API responde con una redirección.

```bash
curl -s https://api-qa.1platform.pro/api/v1/health/ | jq '.data.environment'
```
