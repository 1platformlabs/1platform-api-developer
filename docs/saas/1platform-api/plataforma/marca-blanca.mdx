# Marca blanca

El Panel toma la identidad y las capacidades de la configuración de su espacio. El alta de un espacio, la habilitación de un producto y el permiso de una persona son pasos independientes.

## 1. Solicitar el alta y la habilitación

El equipo de plataforma prepara el espacio y las capacidades acordadas. Esa administración operativa no corresponde a una integración cliente ni se obtiene con un rol de administrador del espacio. La presencia de una guía o un endpoint no activa el servicio; confirme la disponibilidad de cada producto antes de ofrecerlo.

## 2. Preparar el dominio

Acuerde la dirección del Panel con el equipo de plataforma, que es quien la asigna. Puede ser un subdominio `<nombre>-app.1platform.pro` o `app.<su dominio>` cuando ese dominio corresponde a un sitio delegado en la plataforma; en el segundo caso complete los registros y la verificación solicitados. Resolver un host no acredita que el acceso, los módulos o el sitio público estén habilitados. Para un sitio propio, consulte [Publicar con dominio](/docs/saas/1platform-api/sitios-web-y-contenido/publicar-con-dominio).

## 3. Configurar la identidad

La identidad del Panel —nombre visible, logotipos, colores, idiomas y módulos— forma parte de la configuración que prepara el equipo de plataforma; un administrador del espacio no la cambia por API. El administrador sí gestiona el nombre del espacio y la identidad de los correos que salen de él: remitente, dirección de respuesta y pie con enlaces legales.

Un Panel servido en su propia dirección obtiene primero la clave de aplicación de ese espacio (`GET /dashboard/host-app`), después la configuración con marca, tema e idiomas (`GET /dashboard/bootstrap`) y, tras el ingreso, los módulos que corresponden a la persona (`GET /dashboard/modules`). No copie la identidad de otro espacio.

[Referencia de API → Configuración del Panel](/api-reference/1platform-api#tag/dashboard) · [Ajustes guardados del Panel](/api-reference/1platform-api#tag/dashboard-settings).

## 4. Dar acceso a las personas

Use el recorrido de registro y acceso habilitado para ese espacio. Cada persona actúa con su token de usuario y recibe sólo los módulos que le corresponden. El token de aplicación de una interfaz compartida no concede administración ni sirve para seleccionar recursos de otro espacio.

Un administrador del espacio puede gestionar sus usuarios y los permisos que el producto permite; no administra todos los espacios. Los permisos de un comercio o sucursal tampoco sustituyen ese rol.

[Referencia de API → Administración del espacio](/api-reference/1platform-api#tag/tenant-admin).

## 5. Verificar la experiencia resultante

Compruebe identidad, dominio, idioma y navegación con un administrador y un usuario sin privilegios. Un módulo oculto debe seguir protegido al acceder a su URL o API. Los servicios en preparación conservan su disponibilidad declarada. Los [avisos del espacio](/docs/saas/1platform-api/plataforma/avisos) permiten comunicar cambios dentro del Panel sin atribuirlos al personal de plataforma.
