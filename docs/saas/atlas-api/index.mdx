# Atlas API

<p className="lead">La Atlas API sirve el catálogo, las sesiones de los miembros, los derechos de acceso y la entrega de
medios de cada tenant: una biblioteca, un servicio de streaming, una red de podcasts o un sitio de publicación con tu marca.</p>

Un **tenant** es cada sitio o marca que opera sobre Atlas. Todo dato (catálogo, miembros, derechos de acceso, configuración)
pertenece a un tenant, y cada solicitud se resuelve a uno solo.

> Atlas es un producto **independiente** de la 1Platform API: tiene su propio modelo de autenticación, sus propios datos y
> su propia URL base. Si buscas la API de pagos, facturación y contenido de 1Platform, ve a
> [1Platform API](/docs/saas/1platform-api/getting-started).

## Cómo funciona

1. **Cada solicitud nombra su tenant** con el header `X-Tenant-Slug`. Un slug mal escrito no da error: cae en el tenant
   por defecto. Verifícalo primero ([Resolución de tenant](/docs/saas/atlas-api/tenant-resolution)).
2. **El catálogo es público.** Listar, buscar y ver el detalle de un ítem no requiere sesión.
3. **Los miembros inician sesión con un enlace de acceso (magic link)** que se canjea por un JWT. Los operadores del tenant
   usan correo y contraseña.
4. **Un derecho de acceso (*entitlement*)** dice qué puede consumir cada miembro. Lo concede un operador, el acceso
   gratuito automático del tenant o el proveedor de pagos del tenant mediante un webhook.
5. **La entrega** emite un ticket de corta duración (URL firmada o manifiesto de streaming) sólo si el miembro tiene acceso.

## Qué necesitas

Todo lo emite el equipo de 1Platform Labs; Atlas no tiene un alta de autoservicio:

- el **slug** de tu tenant y su dominio principal;
- una **cuenta de operador** del tenant, si vas a gestionar el catálogo;
- una **clave de integración** (`ak-int-…`), si un servidor tuyo va a aprovisionar miembros;
- el **secreto de webhook** del tenant, si operas la integración de pagos que concede derechos de acceso.

## En qué se diferencia de la 1Platform API

| | 1Platform API | Atlas API |
|---|---|---|
| **Credenciales** | Token de aplicación + token de usuario | JWT del miembro u operador, o clave de integración |
| **Alcance** | Espacio de trabajo del token | Tenant del header `X-Tenant-Slug` (o de la clave) |
| **Errores** | Envoltorio `{ success, data, msg }` | `code` estable, plano o anidado en `detail` ([Errores](/docs/saas/atlas-api/errors)) |
| **URL base** | `api.1platform.pro/api/v1` | `atlas-api.1platform.pro/api/v1` |

## Operaciones

| Operación | Para qué |
|---|---|
| `GET /tenants/by-host` | Confirmar el slug real de un tenant a partir de su dominio. |
| `POST /auth/magic-link` | Enviar un enlace de acceso al correo de un miembro. |
| `POST /auth/magic-link/verify` | Canjear el token del enlace por una sesión. |
| `GET /public/catalog` | Listar el catálogo publicado. |
| `GET /public/items/{slug}` | Ver el detalle de un ítem. |
| `GET /delivery/items/{content_id}/playback` | Emitir un ticket de reproducción o descarga. |
| `POST /entitlements/checkout` | Crear el enlace de pago de un plan o ítem. |
| `POST /integrations/bower/v1/members/upsert` | Aprovisionar un miembro desde tu servidor. |

Todas las operaciones: [Referencia de API](/api-reference/atlas-api).
