# Pruebas

Recetas para probar su integración sin tocar datos reales.

## Probar en QA

La URL base de QA es `https://api-qa.1platform.pro/api/v1`. Pida el acceso a su contacto comercial: recibirá
credenciales que sólo funcionan en QA. Tenga en cuenta que QA **no es un entorno estable**: recibe los cambios antes
que producción y puede cambiar sin aviso. Ver [Entornos](/docs/saas/1platform-api/reference/environments).

Los datos de pago de prueba de QA (tarjetas y condiciones) se los entrega su contacto comercial junto con las
credenciales.

## Recibir webhooks en su máquina local {#recibir-webhooks-en-tu-máquina-local}

1. **Expón su receptor local con un túnel** (por ejemplo `ngrok http 3000`, `cloudflared` o similar) para tener una
   URL pública `https://`.
2. **Registre el dominio del túnel y apunta un evento a él.** Las dos llamadas las hace un administrador del espacio
   de trabajo, con su token de usuario en `$USER_TOKEN`
   (ver [Webhooks](/docs/saas/1platform-api/plataforma/webhooks)):
   ```bash
   curl -X POST "$BASE_URL/webhooks/config/domains" \
     -H "Authorization: Bearer $APP_TOKEN" \
     -H "x-user-token: $USER_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"domain": "abc123.ngrok-free.app"}'
   ```
   Después, con `PUT /webhooks/config/events`, asigne a `on_approved` la URL
   `https://abc123.ngrok-free.app/webhooks/payments`.
3. **Cree una transacción en QA, páguela con los datos de prueba** y observe la entrega en su receptor local.

## Repetir una entrega capturada

Una vez que capturó una entrega real (headers y cuerpo), puede repetirla contra su receptor sin pasar por la
API:

```bash
curl -X POST http://localhost:3000/webhooks/payments \
  -H "X-Webhook-Signature: sha256=..." \
  -H "X-Webhook-Timestamp: 1714389600" \
  -H "Content-Type: application/json" \
  --data-binary @captured.json
```

Use `--data-binary` para que el cuerpo viaje con los mismos bytes que se firmaron.

:::caution[Una entrega capturada vence a los 5 minutos]
Pasada la ventana de 5 minutos, la firma ya no verifica. Si necesita repetir la misma entrega muchas veces mientras
depura, amplía la ventana sólo en su verificador de **pruebas**, nunca en producción.
:::

## Prueba de humo

La prueba mínima de una integración nueva de cobros:

1. Canjee sus claves por los dos tokens (`POST /auth/token`, `POST /users/token`).
2. Cree una transacción con `POST /users/transactions` y un `merchant_reference` único.
3. Abra la URL de pago que devuelve y páguela con los datos de prueba de QA.
4. Compruebe que su receptor recibe `event: on_approved` con el mismo `merchant_reference`.
5. Compruebe que la firma verifica y que su receptor ignora la misma entrega repetida.

Si un paso falla, busque el síntoma en [Solución de problemas](/docs/saas/1platform-api/reference/troubleshooting).
